# skilled CLI command reference

skilled supports the full evaluation lifecycle: validate, run, list cases, generate reports, and migrate formats. It also has user configuration and debugging commands.

## skilled run

Run evaluation cases and generate reports:

```bash
skilled run [path] [flags]
```

`path` points to `eval.yaml`. When omitted, skilled looks for `evals/eval.yaml` in the current directory.

| Flag | Default | Description |
| --- | --- | --- |
| `--auto` | `false` | Detect `evals/` automatically; can read Anthropic `evals.json` directly. |
| `--include-case-name` | — | Run only matching case names (glob; repeatable). |
| `--exclude-case-name` | — | Exclude matching case names (glob; repeatable). |
| `--format` | — | Additional `junit` or `html` report (repeatable). `result.json` is always written; `junit` writes `report.xml` and `html` writes `report.html`. `json` is redundant. |
| `--output-dir` | Directory containing `eval.yaml` | Directory for reports and artifacts. |
| `--iteration` | `0` (auto) | Repeat selected cases for stability sampling. `0` appends one run after the last existing `iteration-N/` without summarizing past results. Positive N runs N samples in `iteration-1/` through `iteration-N/`; for N > 1, the terminal summary covers only this command's samples. |
| `--engine` | Configured value | Override the Agent Engine. |
| `--runtime` | Configured value | Override `environment.type` (`none`, `opensandbox`, or `docker`). |
| `--model` | Configured value | Override the model (`provider/name`). |
| `--parallelism` | Configured value | Override `cases.parallelism` (1–256). |
| `--baseline` | Configured value | Set `benchmark.enabled: true`. Requires Docker with a clean image and configured container credentials; native `none` and OpenSandbox benchmarks are rejected. |
| `--api-key` | — | Pass an API key; higher priority than environment variables. |
| `-v, --verbose` | `0` | Default `info`; `-v` gives `debug`; `-vv` or `--verbose=2` gives `trace`. |

Exit code `0` means all cases passed; `1` means a case failed or execution errored. This can gate CI.

### Examples

```bash
skilled run ./evals/eval.yaml
skilled run ./evals/eval.yaml --include-case-name "basic-*"
skilled run ./evals/eval.yaml --exclude-case-name "*-old"
skilled run ./evals/eval.yaml --engine codex --model openai/gpt-4
skilled run ./evals/eval.yaml --parallelism 4
# Requires environment.image and credentials configured for the container
skilled run ./evals/eval.yaml --runtime docker --baseline
skilled run ./evals/eval.yaml --format html --format junit
skilled run ./evals/eval.yaml --iteration 3
# Example terminal summary: case_a: 3 trials, 2 PASS, 1 FAIL -> flaky
skilled run --auto
skilled run ./my-skill/ --auto --engine codex
```

### Optional OTLP traces

With standard OpenTelemetry environment variables, `skilled run` can export traces through OTLP. Verbose logs can include `trace_id` and `span_id`. The user configuration generated by `skilled init` can also set default OTEL variables. See the upstream documentation's User config and CLI reference sections.

## skilled validate

Validate `eval.yaml` and its referenced case files:

```bash
skilled validate [path to eval.yaml]
```

Example success message:

```plain
✓ eval.yaml is valid (loaded 3 case(s))
```

## skilled list-cases

List every case in a configuration:

```bash
skilled list-cases [path to eval.yaml]
```

## skilled report

Generate reports from an existing `result.json` without rerunning cases:

```bash
skilled report <path to result.json> [flags]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--format` | `json` | `json`, `junit`, or `html` (repeatable). |
| `--output-dir` | Directory containing `result.json` | Output directory. |

```bash
skilled report result.json --format html
skilled report result.json --format json --format junit --format html --output-dir ./reports
```

## skilled import

Convert Anthropic `evals.json` to native skilled YAML:

```bash
skilled import <evals.json> [flags]
```

`--output` sets the output directory; the default is the directory containing `evals.json`. `import` is a one-time conversion, whereas `run --auto` reads `evals.json` at run time without writing YAML.

## skilled init

Write a **user configuration template** for telemetry, default `runtime_kwargs`, and other settings. This is separate from evaluation `eval.yaml`:

```bash
skilled init [flags]
```

| Flag | Description |
| --- | --- |
| `--local` | Write `$PWD/.skilled.yaml`; mutually exclusive with `--config`. |
| `--print` | Print the template to stdout without writing a file. |
| `--force` | Overwrite an existing file. |
| `--config <path>` | Explicit output path; mutually exclusive with `--local`. |

The default path is `$XDG_CONFIG_HOME/skilled/config.yaml` or `~/.config/skilled/config.yaml`. `SKILLED_CONFIG` can also point to the user configuration file.

## skilled debug

Debug internal components during development or troubleshooting:

```bash
skilled debug judge <input.json>
skilled debug report <input.json>
```

## Artifact layout

```plain
<skill-name>-workspace/
  iteration-1/
    result.json
    benchmark.json
    report.html          # If generated
    <case-id>/
      with_skill/
        outputs/
        grading.json
      without_skill/     # Only possible with benchmark.enabled=true
        outputs/
        grading.json
```

### grading.json (Anthropic-compatible subset)

The workspace's `grading.json` usually contains only `expectations` and `summary`. Full status is in `result.json` under `case_results[].grading`, including `status`, `turns_executed`, and `assertion_results`.

### benchmark.json

Baseline comparisons add fields such as `without_skill` and `delta`.

## Long evaluations over MCP

For long suites, use `skilled_start` with a stable `idempotencyKey` and the suite
path, then poll `skilled_status` by `runId` and retrieve `skilled_results`. Reuse
the same key and arguments if the connection drops; do not start another run
just because a client timed out. Use a new key for an intentional rerun after
changing a Skill. Background jobs survive disconnection. To stop one, call
`skilled_cancel`, then wait for terminal cleanup. The server must enable execution.
The suite's configured report formats are preserved, with JSON also generated.
